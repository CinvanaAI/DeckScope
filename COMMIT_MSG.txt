--- also in this commit (ninth cycle, the reverse flow) ---

deckscope improve: the audit run backwards - a deck (or a .txt/.md of
raw founder notes: the loader already ingests those, so
build-from-scratch is the same command) in, the strongest version that
survives this tool's own audit out. One schema-validated model call
(the Deck Reviser); everything else is code.

The enforcement layer is the feature, and it is deterministic:
- citations outside the run's own bibliography are stripped by the
  same audit_fragment the pipeline trusts, and the blueprint says how
  many;
- a new or revised line asserting a figure with no surviving source is
  demoted to a visible founder-input slot - DeckScope invents nothing
  in either direction, and a deck-builder that fabricates traction
  would be worse than no deck-builder;
- a kept line that token-matches a contested claim is flagged "kept
  against the evidence (C#)" - keep it knowingly, because an
  investor-side run of this same tool will contest it;
- founder-input lines always carry a visible [BRACKETED SLOT].

Output: slide-by-slide blueprint markdown with per-line provenance
marks, a cut list, the "only you can fill these" list with answer
standards, and an evidence appendix to carry into the data room;
--pptx also writes an editable starting deck. --demo runs the whole
reverse flow offline on the packaged sample deck with a fixture
deliberately authored to trip both guards, so the demo shows the
guardrails working rather than idle. --nda fails closed (exit 4)
before anything is read, and forces research off. improve lives in
deckscope/commands/ per the beachhead rule.

12 new tests (tests/test_improve.py). Board: all 45 test files green,
lint clean 195 files, claims checker holds, demo exit 0.
